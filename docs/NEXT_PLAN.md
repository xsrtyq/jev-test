# Jev Context Curator：证据重整与下一阶段计划 v0.2

核对日期：2026-09-21。状态：实验代码已实现；本次只重算旧实验和运行离线测试，没有启动新一轮付费模型调用。所有作者拟定标签尚未得到独立人工复核。

## 1. 本阶段决策

继续独立实验，但不把 Jev 接入 Coding Workflow Suite。不建立通用 Decision Plane、不扩全局 skills/MCP、不改 Codex/Claude 配置、审批、签名、验收链。没有本地模型设施不是阻碍：Jev 在官方 API 推理，Python 规则及证据回放在 GitHub Actions CPU 上运行。

问题从“Jev 分类是否准确”改为：**在固定上下文预算下，相比普通程序策略，Jev 是否提高必要证据的可用性，是否导致关键约束、版本、失败经历或工具证据消失？** 这还不等于“让 LLM 完成任务更好”，后者需要另一个生成模型的闭环对照。

中文仍为一等输入，不迁移系统语言。只把固定问题模板改成英文是一条单独的消融条件，不能把翻译结果冒充中文效果。

## 2. 旧实验重新核对

原始四个 ZIP 已重新逐条计算，详细结果见 `evidence/verified-v01.json`，文件哈希和原始运行号见 `docs/EVIDENCE.md`。复核确认：base 87/90、reverse_options 84/90、injection 88/90、distractor 88/90；pmax≥0.9 的 310 次关联观测中未见错误。仍只有 30 个原始案例，不是 360 个独立样本。

需要收紧先前解释：

1. 一组反序实验比 base 少对 3 题，是顺序敏感性的线索；没有相同输入重复对照，不能把全部变化因果归给顺序。新实验加入 base/repeat，同时交错运行。
2. 固定顺序只改善可复现性，不会修复偏差；置信度阈值不能由这批旧题的“零错误”直接确定。
3. 加噪声后高一点的准确率、略低的延迟，不能解释为加噪声有帮助，也不能说明处理大上下文几乎免费。
4. 简单 injection 带明确的不可信边界；不是普遍抗提示注入的证明。
5. case-028-zh 的撤销迁移许可被误判为无关，是硬约束不能交给相关性模型降级的具体证据。
6. 上下文筛选比错误类型分类难；已测输入大约是几百到两千多 token，不是数十万上下文或长 coding session。

## 3. 最新外部证据改变了什么

详见 `docs/EVIDENCE.md` 的原始来源、样本与局限。

- **Codex 的负面配对实验**：6 个合成案例、每例两次 continuation；native/local recovery 为 12/12，Jev 与 equal-score 对照为 8/12。候选召回不足、只给短摘要、预算装包都有可能影响结果。不能把失败简单归为模型不行，也不能继续只拿压缩率评价。
- **fast-jev-compaction #65**：一位用户报告工具证据被删而助手进度叙述保留，随后出现 9 次无工具的完成报告。是单个会话的未独立复现实例，不是确立因果或失败率，但要求我们保持 claim→evidence、tool_call↔tool_result 的依赖。
- **#70 的多轮反馈**：两段会话、九次压缩；累积的非候选文本可能越来越大。候选覆盖和多轮装包上限必须显式检查，不因“收益小”就启动另一轮有损摘要。
- **Jevals**：Banking77，300 题×5次；报告相同请求约2.7%翻转、换序约10.3%。其 LLM 基线输出概率且未用严格结构化输出，因此可以借鉴稳定性设计，不能直接沿用其速度倍率作为紧凑小 LLM 对照结果。
- **BorisLeMeec 的正面小实验**：3 组语义审计，平均进入上下文量约下降70%；其中一项召回从1降到0.8。平均F1更高不代表没有漏掉更重要的事实。
- **官方局限**：Jev 1.13 文档明确说明大段无关 state、复杂否定、对抗内容可能降低质量；Noul/Choice/Score 不保证跨形式一致，阈值不可直接搬用。

因此顺序必须是：**先验证证据完整性和失败行为，再看压缩收益，最后才测真正 LLM 的任务成功率与总费用。**

## 4. 实现的边界与数据结构

原始档案始终保留。`state` 只包含 goal、query、step、scope、blocks、background；gold、后续检查答案不发送给模型。每个 block 带真实模拟来源、时间步、scope、pair、depends_on、supersedes。来源由测试环境提供，不接受文档自己宣称的 SYSTEM 身份。

程序决定 PINNED：当前范围有效的可信用户约束。撤销关系由明确的来源元数据维护；旧许可归档，不再作为当前权限。模型不能创建新权限、修改用户目标、通过验收或执行工具。

普通 block 为 ACTIVE 或 RETRIEVABLE；v0.2 不需要再加不可恢复的 COLD/DELETE 逻辑。只返回原文块，所有省略均有归档提示。索引分页，完整原文和哈希留在实验档案。接纳助手叙述时保留其证据依赖；调用与结果按 pair 同进同出。依赖缺失不当作成功。

超预算时优先报告 `blocked_budget`，不能为达到漂亮压缩率丢 PINNED。稳定前缀尽量放在前面，动态 query、revision 放后面。显式测量的是序列化字节前缀，不是服务端 KV 命中。

## 5. 数据集与防止“自证”

新数据：12 个主题族×4个 seed =48 个原始场景组；每组中文/英文/混合，共144个场景版本，每个包含13条记录。主题包括会话、金额、迁移、支付超时、部署版本、权限、TLS、精确中文路径、失败测试、撤回许可、幂等性、旧缓存。

按整个主题族划分 dev/calibration/test，各4族，译文、seed 与扰动不跨组。**这些主题共用部分事件结构，仍不是48种独立真实任务，也不保证OOD泛化。** 现有的30题保留为旧版回归，不混充新测试集。

三类参照：程序可以核验的精确字符串与结构不变量；作者拟定的语义标签；最终真实工作流任务验收。前两类不能替代第三类。模型不出题后自己裁判。`needed/constraint/exact` 的二值诊断明确为 provisional，`unresolved` 不因推测未来而强配标签。

测试集不得用于改 prompt 或挑阈值；修改任务定义/模板后升级数据和计划版本，并使用新留出案例。独立人工复核缺席时，只报告探索结果。

## 6. 对照组

同一预算同一状态：

- keep_all：不压缩参考，超预算如实标注，不算预算内胜利。
- recency：最近信息优先＋同一 PINNED/依赖规则。
- lexical：英文词项＋中文二元词片的简单相关性＋同一规则。不是 BERT、embedding 或小神经网络。
- equal_score：相同程序装包流程、没有模型语义分数，分离“规则/排序程序”的收益。
- Jev Choice：keep/archive/uncertain，仅作为建议。
- Jev signals：needed、constraint、exact、unresolved 四个独立 Noul。max 合并是保守策略，不是经过校准的联合概率。
- Jev Score：四级保留必要性，完整概率保留；不是精确数值计算器。
- 可选云端小LLM：严格 JSON Schema，批量紧凑标签，不要求理由/概率。代码有适配器，但没有本次模型密钥，不运行、不冒称比较完成。

同一 Jev 响应可离线试 2400/3000/3800 字节的上下文预算；这不新增请求，也不伪造模型输出。预算包含归档索引、告知文字和依赖记录。中文与英文的字节开销不同，因此按语言同时看原始判断和装包结果，不把预算差异当语言模型能力差异。

## 7. 手动运行的六组实验

| suite | 默认dev规模 | 最大Jev请求 | 用途 |
|---|---|---:|---|
| quick | 2主题×1seed×3语言×3形式 | 18 | 先验证新协议、批量判断、统计和保留边界 |
| quality | 4主题×4seed×3语言×3形式 | 144 | 冻结拆分后的质量和形式对照 |
| robustness | 6语言场景×6条件 | 36 | 相同重复、候选换序、记录换序、工具结果内注入、120字符短视图 |
| scaling | 6场景×4噪声档×2位置 | 48 | 噪声0/2k/8k/16k UTF-8字节，证据在首/尾；实际token读API usage |
| fanout | 同一场景，两次重复，batch=1/4/13 | 36 | 完全相同问题集合，拆分/合并请求，比较总时间、计费与答案 |
| replay | 6场景，10/20/50环境步 | 18/30/66 | 每5步和目标切换时检查，原文档案保留、各策略独立演化 |

规模按固定计划生成；不是“50步就一定50次模型调用”。没有一个模型看到尚未发生的未来查询。replay 的检索在可观察的查询变化时用 lexical 搜完整档案；不使用 gold ID 定位，查不到就失败。分别记录候选召回、装包召回、后续复核召回，不能把“有指针”当成“已经取回”。

实验采用固定种子的交错顺序，减少时间段负载差异。原请求、问题、代码、计划、源commit均记录哈希；响应版本变化直接停止。概率舍入只在明确小范围内规范化用于计算，并同时保留原始分布和规范化标志。

## 8. 指标与判定

首先看：有效用户约束是否由程序保持、依赖是否孤立、精确路径/状态是否保留、必要证据召回、过期结果是否被误用、候选遗漏、高概率错误降级、运行失败与预算阻断。预算阻断不能算完成。

之后才看：序列化字节削减、Jev API input/output token、真实请求数、客户端p50/p95、全部已知费用及未知用量。按语言/问题形式报告；Brier只对匹配含义的二值维度计算，不把不同primitive的confidence比较成同一个量。

按主题族聚类的bootstrap仅为探索区间；当前每split只有4个主题族，不能据此证明1%退化以内或生产零失败。输出中强制写明 evidence-only，不用 `task success` 名称包装代理指标。

继续研究候选条件：至少一个有限用途在同预算下不弱于程序baseline，或者在相同必要证据保留水平下减少上下文；发现关键约束/孤立叙述等问题先修防护再继续。目标可探索20%以上字节节省，但不是硬性追分线，更不能以删除困难案例达成。

若规则已足够、Jev高概率降级关键证据、短视图导致候选信息丢失、回退使上下文总量或时间更高，则结论可以为“不接入”。不靠这48组题反复调到赢。

## 9. 缓存、成本与长任务的最后验证

v0.2只提供 cache 成本情景计算和序列化前缀长度代理，未知 KV显存、原生cache命中均为null。压缩可能破坏已有缓存；输入减少不能直接换算成Codex订阅节省。

真正的下一阶段，在当前证据测试有信号之后，需要同一个下游生成模型/版本/工具权限：不压缩、纯规则、Jev＋规则三路，从同一初始状态重新运行真实小任务，比较任务验收、恢复次数、全部模型/检索/失败成本、cached/uncached输入与时延。不把基线路径后来的成功轨迹接到新决策后。这部分不在v0.2实现内，也不能用JeV-only fixture替代。

## 10. 安全与预算

模型调用默认dry-run；只允许手动workflow、明确勾选paid、密钥来自GitHub Secret。每次至多240请求、模型估计预算$0.25；socket15秒、程序总时长600秒、Actions job15分钟。单层、零自动重试；429/529等失败保留记录并停，避免重试掩盖延迟。

预算账本在请求前预留，成功按usage结算，计量丢失立即停。它是单次运行保护，不是供应商发票上限或跨运行统一限额。拒绝超字节防护的请求，不偷偷截断；官方tokenizer未公开，不把UTF-8档位当准确token数。官方当前32k单问题/64k整次上限另需核对。

Artifacts不包含密钥，只包含合成资料、请求体、响应结构、统计和计划。上传前扫描密钥原值/常见模式；日志不写服务端异常正文。Actions可能有独立运行时长费用。密钥管理、充值和真正派发由用户控制。

## 13. 两条独立主线：hard retrieval 与 Jev → LLM decision assist

retrieval/dev + calibration 的旧题过度依赖显眼 path/ID；修正 structured regex 后 deterministic top4 在两组上都达到12/12，因此冻结旧 retrieval/test，不再把它当 Jev 增量证明。

新 retrieval_hard 使用：
- 64条 archive；
- 近似主题和错误理由干扰；
- “为什么拒绝/为什么选择”类 query；
- deterministic hybrid top16 candidate generation；
- Jev 只做候选内语义 rerank；
- candidate recall 与 rerank recall 分开计分。

这更接近最终生产形态：deterministic 层负责高召回，Jev 只在语义歧义处增加排序信息。

与此同时恢复最初假设的独立测试：Jev 不直接接管判断，而给下游 LLM 提供语义建议。见 docs/DECISION_ASSIST.md。

配对 arms：
- raw LLM；
- neutral 0.5 signal control；
- Jev direct Choice advisory；
- Jev multi-Noul signal advisory。

核心统计不是单独 accuracy，而是 raw→assist 的 helped / harmed 配对翻转，以及成本、延迟、语言、task type。任何 action_gate 的 harm 都必须单独检查。

这两条线均通过后，才能进入真正端到端 coding task：retrieval/curation 负责输入证据，decision assist 负责低成本语义特征，最终 LLM 仍受 deterministic permission/safety policy 约束。
