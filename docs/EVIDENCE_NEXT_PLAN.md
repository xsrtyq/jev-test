# Jev 下一阶段：证据优先实验 v0.5

日期：2026-09-21。基线仓库提交：`4678c5ca18ae7842ebb8a3734dd864d8e9eaf249`。

## 决策

不把 Jev 降格为只能投票的第二判断器，也不继续无条件给强 LLM 塞概率先验。下一阶段只验证一个可证伪目标：**Jev 能否替下游模型完成一部分证据搜索和选择，在保留决定性原文的同时改善整体质量或资源消耗。**

实现留在 `jev-test`，不修改 Coding Workflow Suite、InvoiceFlow、Codex/Claude 配置、权限体系或验收链。旧实验源文件保持不变。本轮交付新实验程序、审计记录、离线验证和手动云端入口，不代替用户启动付费调用。

## 1. 先把现有证据解释准确

本次从现存 ZIP 重新计算了五份原始结果，审计见 `evidence/audit-before-v05.json`；运行 `python -m evidence_lab.audit <原始ZIP所在目录> --out <新文件>` 可重算。

| 已有实验 | 已核对结果 | 能说明什么 |
|---|---|---|
| 64-block 全量 Jev 检索 | dev/calibration/test 各12/12 Top-1，共36/36 | 在这套作者构造的单目标资料中有很强的检索信号 |
| 旧 Top-16 预筛 | 6/12、6/12、4/12，共16/36 | 这个具体词项/规则实现漏召回，不代表所有 BM25、嵌入或混合检索都不行 |
| hard/dev Raw 与 direct prior | 均24/24正确完成 | 没证明 direct prior 增加正确答案；原始场景仍有天花板效应 |
| hard/dev signals prior | 21/24正确完成，含2次输出上限 | 这一版多概率提示的可靠性和成本不利，应暂停 |
| 推理 token | raw 9,096；direct 10,247；signals 11,563 | 简单 quick 中的节省没有在此复杂样本稳定复现 |

**需要撤回一项过强的安全解释。** 检查原 `assist/core.py` 发现，错误先验的 `synthetic_known_wrong` 和 `synthetic_known_wrong_direct_advisory` 标记进入了下游模型可见文本。这相当于提示了“这是故意造错的建议”。因此，旧结果不能证明下游对**未标明的**高置信错误先验具有抵抗力。旧数据保留，不事后篡改；这项观察只能描述带警告的实验条件。

64-block 资料也有明显模板便利：很多干扰记录自带“另一事件/旧结论”提示，目标常是直接陈述理由的记录。36/36 不是任意长期 coding 记忆的保证，更不能把36个翻译记录当作36个独立真实任务。

旧 prior 分支暂不扩跑 calibration/test；这不是宣告技术永久无效，而是当前接法没有达到继续投入的证据门槛。

## 2. 新问题与四条对照

使用同一份新的档案、同一个下游模型、同一个问题和输出契约，对比：

| 路径 | 输入给下游的内容 | 测试的增量 |
|---|---|---|
| `raw` | 全部原文档案 | 原始能力与成本基准 |
| `rules` | BM25词项/中文双字片排序后、固定预算内的原文 | 不调用 Jev 的整理收益 |
| `evidence` | Jev分片评分、统一重排、依赖闭包后的原文 | Jev 是否替模型减少查找材料的工作 |
| `proposal` | **与 evidence 完全相同的原文**，再加候选标签和引用ID | 在同一证据上，带引用的候选是否比只给证据更好 |

Jev 不自由生成摘要。程序只恢复原始记录；候选引用必须来自已选原文。引用存在不等于逻辑已被证明，所以候选始终是非权威建议，不能授予权限或触发动作。

下游保留此前已跑通的 `A2Agent → deepseek-v4-flash`，不同时换模型、输出模式、问题难度和检索方式。实际中转上游版本仍未独立核验。更弱模型、关闭 reasoning、跳过主 LLM 的路由实验，等本轮获得正面信号后再单独做协议探针与冻结对照；本轮不假定这些能力可用。

## 3. 分片检索的实现

档案规模128与256条。按原档案顺序和字节预算分片，每片最多32条、24,000 UTF-8字节，**遍历全部片**。这是无语义遗漏的切块，不是按时间、项目、scope猜测哪些片不重要。跨项目或旧时间桶也可能包含依赖，不能仅因“硬元数据”就不查。

每片 Jev 做相关性评分，保留前4个候选；各片概率**不直接当成已校准的全局分数**。候选合并后，再放进同一个问题上下文做一次 Jev 重排，最后取前8条并恢复完整依赖和 tool call/result 配对。

所有 compact 路径的原文包采用同一个7,800字节预算，包含规则、查询和提示，不只是文本正文。超预算的依赖组不拆碎，遗漏会计入指标；必要简介本身超预算则显式失败。Raw 路径保留完整档案，不伪装成同样预算内的方法。

程序记录局部候选丢失、合并候选、最终原文包、预算遗漏、依赖闭包和原文一致性，能区分“分片阶段漏掉”与“统一重排/装包漏掉”。

## 4. 新数据不是单纯把旧题扩容

采用可重算的**两记录关联模拟器**：一条原文说明对象当前修订号，另一条说明该修订、该范围的状态。允许、拒绝、资料不足三种结果均衡；缺少当前状态时必须 unknown。决定性记录故意分布在不同档案区段，同时存在旧修订、其他scope、错误助手观点和文档内指令。

每个完整 split 有两个不同任务族 × 三种结果 × 中文/英文/混合，共18条案例。dev为发布许可与产物核验；calibration为模拟付款与重试；test为访问范围与响应契约。每条128或256块，语言配对保持相同ID、事件事实和布局。相同主题的模式、语言、规模与重复都属于关联观测。

标签来自明确的模拟器规则，不用 Jev 或另一个 LLM 给自己裁判。原文包含推导需要的事实；缺失案例不暗示答案。但它仍是作者设计的模拟任务，**不是独立人工金标准，也不是真实项目验收**。规则型关联题本身可能被专门程序很好地解决，这是允许的结果，不应为让 Jev 赢而隐藏规则基线的优势。

## 5. 输出与评价

下游只返回一个 JSON 对象：`decision` 加三个原文引用槽位 `e1/e2/e3`，未使用的引用为 `NONE`。主指标要求**标签正确且必要原始证据ID被引用**；只猜对标签不够。

JSON模式之后进行本地严格校验，拒绝多字段、未知枚举、不存在的引用。引用ID只在本地校验，不把全部档案ID重复塞进三份输出schema，避免人为膨胀 Raw 输入。

主要记录：

- 决策正确率、必要证据覆盖的正确完成率、missing/unknown场景、错误allow；
- 每一臂相对Raw的 helped/harmed，输出上限和未完成全部留在分母；
- 分片候选召回、合并后证据召回、原文与依赖完整性；
- 下游输入、输出、reasoning、缓存输入统计；缺失usage为unknown而不是0；
- 每次决策的整条路径成本与串行耗时，再对这些总耗时求p50/p95；不混合Jev单次耗时与LLM单次耗时来算“端到端p50”。

实验账单与生产式估算分开：实验里相同的Jev检索结果在四臂和重复之间复用一次；生产式每次独立决策均把对应的Jev预处理成本重新加进去。缓存命中量能记录就记录，但本轮估价不假装知道A2Agent账户组折扣或缓存折扣，也不声称能节约Codex订阅额度/KV显存。

## 6. 阶段与请求上限

| stage | 案例 | 每案档案 | Jev最多 | Flash最多 | 用途 |
|---|---:|---:|---:|---:|---|
| `smoke` | 3 | 128 | 18 | 12 | 只检验链路、引用契约和预算，不推断质量 |
| `retrieval128` | 18 | 128 | 90 | 0 | 检查分片、合并、依赖与缺失证据 |
| `retrieval256` | 18 | 256 | 162 | 0 | 不改参数扩大档案，检查扩展损失 |
| `e2e128` | 18 | 128 | 108 | 144 | 四臂、两波，测正确完成和整体资源 |
| `e2e256` | 18 | 256 | 180 | 144 | 上一阶段有信号后验证更大规模 |

顺序：**smoke → retrieval128 → e2e128 → retrieval256/e2e256**。不会自动连跑。若128阶段已显示必要证据频繁漏掉或Jev比程序基线更贵且没质量收益，就先停止，不刷256规模。

e2e的两波不是同案连续重试，而是先跑完所有案例的第一波再跑第二波。每个案例的四臂循环换位，Jev原始结果冻结复用。这个安排减少固定执行顺序的偏差，但不是完美平衡设计，更不是跨天稳定性测试。后续可用同一份冻结计划，在另一个时间窗口重跑一次，不能选择性保留好结果。

## 7. 继续/停止的门槛

所有当前阶段只决定是否值得做下一轮，不构成生产上线许可。

1. 协议门槛：无秘密泄露、伪造引用、静默截断、漏计费；计划请求完整，或缺失被明确报告。
2. 证据门槛：必要信息与引用能够跨片恢复；若规则基线已同样好，必须看Jev是否还能减少整体成本或显著提高困难样本成功率。
3. 收益门槛：不接受“下游input少了”作为唯一胜利。希望看到相同正确完成水平下整条路径成本或延迟有至少约20%的**探索性**改善，或同预算质量改善；样本小，仍需新留出族复验。
4. 风险门槛：出现错误allow、显著harmed或输出上限增多，要优先分析，而不是升token上限掩盖失败。
5. 冻结门槛：dev定参数；calibration检查迁移；test冻结后一次报告。若暴露数据/协议错误，升级版本和新留出集，不把已经看过的test继续叫untouched。

## 8. 故障与预算控制

默认dry-run；只有手动勾选才发送请求。Jev预算保护$0.25，Flash $0.75；最多240/160请求。它们是每次运行的估价保护，不是供应商发票保证，恢复运行也有独立新调用账本。两后端共享1,200秒deadline，Actions有25分钟上限，避免之前“Jev自己的时钟在等下游时已过期”的问题。

输出2048 token上限不再自动提高；有有效usage的截断记censored、保留全部成本、继续其他独立样本，不自动重试。认证、限流、模型标识改变、未知用量、传输错误则停止并保存部分产物。

每次请求先写intent、后写result；计划、代码、配置和请求体有哈希。可从同计划/同协议的旧artifact恢复，只复用已经完成且有计量的结果；已发送但结果不确定的请求不会偷偷重发。也可指定case_id跑一条，但那是独立新调用，应保留来源，不能覆盖旧样本。没有实现“自动挑最好的一次”。

## 9. 当前实现边界

已实现：128/256完整分片扫描、候选统一重排、原文与依赖打包、四臂证据决策、引用校验、缺失资料场景、两波设计、正确端到端统计、请求级日志、恢复、离线测试、手动Actions。

尚未完成且不声称验证：真实coding项目闭环、实际工具执行、生产上下文管理、跨库权限提取器、多语言embedding/neural reranker对照、更弱模型迁移、可信概率校准、未标记错误候选的盲法鲁棒性、跳过LLM的自适应路由、服务端KV优化。未来的干预盲测必须使用与正常候选相同的可见格式，错误标记只留在评测侧。
