# 实验决策：先尝试证伪，不为 Jev 重构系统

## 第一轮实际实现的范围

这是依赖 Python 标准库的命令行实验台，不是新的 agent 平台。首轮比较规则、Jev API、紧凑结构化输出的小型 LLM。可选本机协议适配器只是接线，不包含模型引擎与权重。

模块路由、错误分类、上下文相关性各 10 个原始案例，每例有中文、英文和混合条件。30 个原始案例、90 条记录全部属于 smoke，标签尚待人工复核。不得用于证明中文能力足够或达到生产级可靠性。

## 用户的三个问题及可证伪假设

1. 小 LLM 路由不新鲜。只有在相同语义输入、同样批量化、紧凑输出、近似质量下，Jev 仍显著更快/更便宜，才说明它有增量价值。不能把冗长 JSON 生成器当成唯一基线。模型未公开权重/全部训练细节，本实验不能分离所有架构与训练贡献。
2. 高置信错误可能污染后续任务链。准确率、概率校准、任务成功率是三个不同指标。按任务及语言分别查看 high-pmax 错误、关键约束遗漏、拒答/升级需求；置信度从不授权执行。真实长任务的必要条件是能检测、恢复、重新规划，而非追求每一步都无误。
3. 不为一个候选依赖把整个系统改成英语。首先保持中文状态，比较中文/英文固定问题模板。若必须逐次翻译才可用，将翻译和回退的质量、延迟、费用一并算入；现版本不内置翻译，不把翻译损失藏起来。

## 下一阶段（尚未实现或执行）

- 完成人工审核；在有信号时扩展到 300 个基础案例，按原始组分割 60 开发 / 60 校准 / 180 冻结测试。翻译、改写和选项换序同组，不能跨分割。
- 用校准集选阈值，冻结测试只验证；不得在测试集挑一个漂亮阈值后宣布通过。当前 0.9/0.95 分桶仅用于诊断。
- 真实独立闭环：相同的下游 LLM、相同初始状态；实际重新执行模拟工具分支，比较任务成功率、总成本、p95、误路由造成的额外步骤、恢复成功与人工介入。
- fault simulation 只有独立错误及完美恢复假设，不代表真实 Jev 错误率，不是上述闭环的替代品。
- 可选本地模型和同权重生成/直接读出消融；先确认现有硬件，不买硬件、不改全局驱动、不训练。

## 停止或继续

发现中文高置信错误、关键约束遗漏、几乎全部需要回退、网络使总时间变差，或者规则/小 LLM 已经足够：保留反例并停止扩展。外部英语 benchmark 不能推翻本地任务上的失败。

只有找到低风险、可恢复的任务类别，且目标语言质量未显示有意义退化，全部调用/翻译/回退后仍有收益，才值得进一步影子测试。初始 20% 成本/大模型调用下降或 15% p95 下降可作为探索目标，但都不是已实现结果，也不是自动上线条件。

不把模型答案写进事实存储。将原始用户约束保留在不可丢弃的证据区，候选资料排序和实际删上下文是不同动作。权限、支付幂等性、签名、验收、发布决策仍由原系统和人掌握。

## 计费与隐私

所有真实远程调用必须同时有网络开关、付费开关、有效配置和本机密钥。原始 state 不写日志，但数据文件及输出标签本身也可能敏感。只先用合成样本。

预算为每次 run 的应用端估计；价格表不是供应商账单，未知用量不能按零处理。遇到服务或计量错误暂停后续调用，不自动重试。缺少总墙钟 deadline、跨运行持久预算和自动配额对账，禁止宣传“绝对不会超预算”。
